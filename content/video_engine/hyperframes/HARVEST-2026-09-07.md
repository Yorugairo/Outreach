# HyperFrames harvest — 2026-09-07

The operator (2026-09-07, after P47 T1–T5 landed): *"we might as well download all of these components, they're single-file
HTML components. Then we should learn from them or add them directly as capabilities. Don't modify our stuff that's already
working with these components. These become references or tools we can quickly reach for, or fill gaps that we didn't have
available, and also exploration/play objects and learning opportunities."*

Fourteen components pulled verbatim (twelve, then drift-hold and morph-text the same morning) with the project's pinned CLI (`npx --yes hyperframes@0.7.101 add <name>`; the project
pins 0.7.101, the registry is at 0.8.30) into the hyperframes lane, beside the ones P35 ported from:

- `compositions/components/*.html` — thirteen primitives (paste-into-a-composition snippets, each a paused GSAP timeline)
- `compositions/hw-text-cloud.html` + `assets/fonts/Caveat-700-latin.woff2` — one block composition (its own document)

**The rule that binds:** nothing in the player template, the compiler, the gate or the kinetics modules changes because of
this harvest. What already works (E44/E45's docks, the mount, the spiral, the dip and blur-zoom, the idle, build-on,
stop-action, the morph) stays as it is. A component here is one of three things — a **tool** we reach for in the hyperframes
lane as-is, a **lesson** whose mechanism we port into our own kinetics when a slice asks for it (the P35 way: mechanism
only, never the runtime), or a **play object** to explore in the lane's preview (`npm run dev` here). The classification
below is the parent's first read; the operator's notes are quoted where they exist.

| **morph-text** (added the same morning) | The classic GOOEY text morph: two texts stacked; over `morph_speed` (1 s) A blurs OUT (blur up to ~8 px) and fades while B blurs IN, and the whole display sits under an SVG `feColorMatrix` alpha THRESHOLD (`0 0 0 255 −100`: alpha slope 255, intercept −100) so the two blurred silhouettes fuse into one liquid shape mid-morph — the same trick as the gooey/ink-blob effect. ## What this is not

- Not a change to the engine. Every row above that says **lesson** is a candidate slice, written into the backlog (R26-15) and
  taken up only when a short asks for it and the operator says so — E48: the primaries and accents are decided by the next
  shorts' curves, not by a catalogue.
- Not doctrine. The intake (`docs/content-video-engine/HYPERFRAMES-INTAKE-2026-09-06.md`) already gated HyperFrames' claims
  against the vendor pages; this harvest adds the CODE those claims ride on, verbatim, so a port reads the mechanism instead of
  the prose.
- Not the hyperframes runtime. As with P35, when a mechanism is ported it comes across as math on our painter (a pure function
  of `t` behind a kinetics flag), never as a GSAP timeline in the player.
