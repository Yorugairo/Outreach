### The token, and why that form

`;domain=<ymin>,<ymax>` on the ledger token — the y scale the page is **born** on, written onto the page's own
`axes` at load. Three reasons for that spelling, and they are the row's answer to its own "(or `domain=`)":

1. **It names the key it WRITES.** `axes.domain` is what the page spec carries, what a derived rescale state
   carries (`rescale_state`, `:2464`) and what the player reads — so the born state and the state a transition
   moves to are described by ONE word instead of two spellings of one idea. `;ymin=..;ymax=..` would name
   neither the key nor the pair.
2. **A domain is an indivisible pair**, and the plate-option grammar already spells a compound value as a comma
   list inside one token (`plane=quad:<8 numbers>`, `throw=<grow>,<from>,<s>`). Two options for one scale invites
   a half-declared scale, which is a new ambiguity nobody asked for.
3. **Both ends are required, and both must be FINITE.** The first half is a measurement, not taste: the line
   builder tolerates a null end (`:8680-8681` test each), the bars builder does not — `:8445` reads `dom[0]` and
   `dom[1]` straight into its scale, so `hi = null` is a NaN plot. The second half is the reviewer's round:
   `float("inf")` satisfies `hi > lo` outright, so `;domain=95,inf` (and `-inf,130`) used to be written onto the
   page's own `axes` for the player to divide by. Both are refused by name in the parser (`:3540`), which is the
   one place the grammar pass and the page pass both go through.

### Changed

- `build_scene_timeline_f.py:111` — `PLATE_OPTS` gains `domain`.
- `:3513` `DOMAIN_BUILDERS = ("dense-line", "story")` — the two builders that read `axes.domain` **on purpose**,
  with the engine lines that read it named in the comment, and **`:2476` `rescale_state` now reads the same
  tuple** instead of its own copy of the pair: the builders a rescale admits are the builders a born domain
  admits, for the same reason. One law, written once. **The comment says what the bound IS** (the reviewer's
  third point): a CONSERVATIVE bound, not an exhaustive one — the engine's builder dispatch falls back to the
  bars builder for a kind it has no painter mapped for, so a page whose builder is `object` would in fact read
  the domain through that fall-back. Refusing it is the choice, and the reason is legibility of intent: a scale
  honoured by accident, on a page whose own builder never asked for one, is a number the author cannot predict
  and a gate cannot read. A third builder joins the tuple when its OWN painter reads the key — never because a
  fall-back happened to. Pinned by `test_the_builder_bound_is_the_conservative_one_and_says_so`.
- `:3524` `page_domain_spec(value, builder, where)` — the pair, validated (two numbers, both finite, `ymin <
  ymax`); the builder bound checked only when the page is in hand (`builder=None` from `_check_opt` is the
  grammar-only pass, as `page_field_spec`'s is).
- `:2999` — `_check_opt` routes `domain`.
- `:3833` — `world_for_plate` pops it, refuses it by name on a world that is not a page (*"a plate is a picture
