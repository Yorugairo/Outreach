## R26-218 — A MARK NAMES ITS SERIES, ON THE PAGE THE EYE IS LOOKING AT

```
Recall: docs/content-video-engine/BACKLOG.md:649  ("reads `linePts[tg.series | 0]`")
Recall: docs/content-video-engine/samples/scene-evidence-engine.mjs:8927  ("a datum's position THIS FRAME - the active state's, LERPED from the leaving state")
Recall: docs/content-video-engine/samples/scene-evidence-engine.mjs:8958  ("a datum resolves against the ACTIVE chart state")
Recall: docs/content-video-engine/CAPABILITIES.md:20  ("annotation MARKS that land when the line reaches them")
Recall: docs_find 0 hits for "linePts"
```

### What was wrong — measured, not read

The `datum` branch of `resolveTarget` asked the DOM and a draw-order list for
things the page indexes by name:

1. **`linePts[tg.series | 0]`** — `linePts` is pushed once per **stroke in draw
   order** (`:8806`, inside `drawn.forEach`), and the ROOT state's list is the
   page **as built**, never the page standing after a `rescale` / `extend` /
   `recast`. The row's premise (*"a page's `linePts` carries one series"*) is a
   symptom; the defect is the **index space and the state**, and it bites hardest
   on a page carrying a second chart state — which the H unit's `s01` does (two
   states, a `rescale` at 4.28 s and another at 29.25 s, a `figure` at 37.64 s).
2. **every `querySelectorAll` spanned the whole world element** — every state's
   `svg.lp-chart` plus `lp-perform`, `lp-morph`, `lp-remake`. So the first
   `.bar` could belong to the bars state that has **not arrived yet**, and the
   n-th `.ser` to another state's first line.
3. **the `figure` builder knew only `sp.series`** — so `target: {kind: "datum",
   series: n, index: i}` (how the H unit authored its `-64%`) was written at
   series 0's datum, and `tier: n` (P50 T9, the author's word for a band on a
   tiers page) was ignored entirely.

### Measured, before → after

Ring on `{kind: datum, series: 2, index: last}`, distance in **stage px** from the
ring group's centre to each series' own last datum, read on the served player
(RECALL-RECEIPT §4 — a frame is a picture, most defects are geometry):

| case | before | after |
| --- | --- | --- |
| plain multi-line page, no second state | series 2 **0.3 px** (already right) | series 2 **0.3 px** |
| line page carrying a `then=` **bars** state, ring before the recast | **122.8 px** off series 2 — it rang the un-arrived state's last **bar** (centre 1030.3, 1514.7) | **0.3 px** (centre 1079.7, 1402.3) |
| page **rescaled**, ring after it | **225.3 px** off the live series 2 — it rang the state the page was BUILT in | **0.3 px** |

Figure on a three-band tiers page with `tier: 2`, distance from the written
number's centre to each band's last datum: **before** it was written on band 0
(the bug never read `tier`); **after** band 2 is the nearest at 48.5 px, band 1 is
102.0 px and band 0 — where the bug put it — is 252.5 px away.

### Changed

- `docs/content-video-engine/samples/scene-evidence-engine.mjs:8970` — new
  `lpSeriesRange(S, si)`: the datum indices ONE series has on ONE state, in the
  page's own index space (`windowOffsets[si]` + what that state drew, the stroke
  mark's `k0` included so a highlighted line's muted history counts). This is the
  clamp the branch shipped with (`Math.min(index, pts.length - 1)`), asked per
  series — so `index: 1 << 24` (the ring's own `ringXExtent`) still lands on the
  last datum and the flag placement is unchanged.
- `docs/content-video-engine/samples/scene-evidence-engine.mjs:12414` (the
  `datum` branch of `resolveTarget`) — one question asked of the page:
  `lpDatumNow(lpst, tg.series | 0, <clamped index>)` on the **active** state,
  mapped through **that state's** chart svg; the bar and `.ser` fallbacks scoped
  to the same chart. The world-wide query survives only for a world that carries
  no page state at all.
- `docs/content-video-engine/samples/scene-evidence-engine.mjs:10871` — the
  figure builder resolves its series by the perform layer's rule **verbatim**:
  `const fsi = (sp.series ?? sp.tier ?? (sp.target || {}).series) | 0;`. `tier`
  is read, and an authored `null` falls through instead of collapsing to 0.
- `content/video_engine/scripts/build_scene_timeline_f.py:730` —
  `_validate_target`'s `series` check was `not isinstance(v, int)`, which let
  `True` through (a bool **is** an int in python) and let a negative through: now
  a non-negative int or a named error. The UPPER bound needs the page's series
  count, which that function has not read.
- `content/video_engine/scripts/build_scene_timeline_f.py:944` / `:957` /
  `:961` / `:964` — `page_series_count(spec)` (a line page's `series`, a tiers
  page's `tiers`; 0 = this page cannot be counted and bounds nothing),
  `TARGET_SERIES_FIELDS`, `SERIES_NAMING_SPECIES` and
  `check_target_series(world, row_species)`: a `series`, a `tier` or a
  `target.series` past the page's last series is a build error naming the number,
  the way `chart_to extend` refuses a `to_index` past the last datum. The bound is
  the **widest** of the page's own chart states, so a recast into a page with more
  series is not refused. Wired at `:2629`, the top of `derive_rescale_states` —
  the one pass that already holds the row's species **and** the page they draw on,
  and whose `ValueError` the row loop turns into a `FAIL: shot row n`.
  **`SERIES_NAMING_SPECIES` is the scope, and `chart_to` is the counter-example
  that earned it:** `chart_to extend {series: n, later: true}` names a series the
  standing page has NOT drawn — the verb reveals it from the evidence object — so
  its `series` is a verb argument, not an index into the page's marks. Bounding it
  refused two live `extend` cases (`test_chart_transitions`) on the first run; the
  own-field check now applies to `TIER_SPECIES + (span,)` only, and
  `target.series` to every species that takes a `datum` target.

**Why the compile-time bound is part of this row.** R26-218 changes a silent
wrong answer into a silent *no* answer: a series the page does not have used to
resolve to the first line and now resolves to nothing, so the species draws no
pixel. That is the right player behaviour (P48 T2 — never the wrong point) and an
unacceptable build, hence the refusal.

No kinetics / species module changed (`sync_kinetics --check`: *in sync (42
module(s): 18 kinetics, 24 species)*), and a plain single-state page resolves to
the same bits it always did — which is why the goldens are untouched.

### Residuals the reviewer named, and one behaviour change to expect

- **the `.ser` draw-order fallback survives at `:12437`** —
  `(chart ? chart.querySelectorAll(".ser") : ...)[tg.series | 0]` is still an
  index into the DOM order of one chart's paths, reachable when `lpSeriesRange`
  or `lpDatumNow` return null (a page whose builder registers no `s<si>` mark and
  pushes no `linePts`). It is now scoped to the active state's chart, so it can no
  longer cross states, but within a chart it is draw order and not the series
  index. Nothing measured reaches it today.
- **`lpSeriesRange`'s second term at `:8974`** reads that same draw-order list
  (`((S.linePts || [])[si] || []).length`) for the count when a series has no
  stroke mark. It bounds only the clamp, never the position.
- **behaviour change on recompile:** a datum outside the post-rescale window now
  resolves to nothing rather than to the built page's point, so an OLD project
  build whose mark named a datum the arriving window dropped will lose that mark
  when it is recompiled. That is `lpMarkDatumOn`'s documented rule (P48 T2)
  reaching the stage layer for the first time; a lost mark is an authoring fix
  (name a datum the window keeps), not a regression to undo.

## R26-219 — A NOTE OR FIGURE THE PAGE WRITES DOES NOT SURVIVE A `chart_to`

```
Recall: docs/content-video-engine/BACKLOG.md:650  ("the railway page's two notes and its `-64%` figure were still standing on the GDP page eight seconds after the recast")
Recall: docs/content-video-engine/CAPABILITIES.md:57  ("RETRACT: on the scene's last 1.0 + 1.0 s every colour on the page is a particle")
Recall: docs/content-video-engine/samples/scene-evidence-engine.mjs:11068  ("a recast or morph takes the line - the bracket leaves with it, on the same clock")
Recall: docs/agent-memory/operator/dip-is-a-world-change.md  (E99: "apply a correction at its own width" - a rescale is not a world change, so nothing leaves on it)
Recall: docs_find "note species" -> the effects card page_species:note ("A line of handwriting appears in the page's quiet zone on a word")
```

### What was wrong

`paintPerform` read, in full:
`nt.div.style.opacity = t >= nt.sp.at ? "" : "0"` — a note, once written, stood
for the rest of the **scene**. Same for `figure` (its group opacity is `1` from
`sp.at` on), `retitle` (erased only when the *next* retitle fires) and `spread`.
Only the `bracket` had a leave, and only on `recast` / `morph`.

### Changed — one law, decided in the compiler, run in the player

- `content/video_engine/scripts/build_scene_timeline_f.py:375-377` —
  `PAGE_BOUND_SPECIES = ("note", "figure", "retitle", "bracket", "spread")`,
  `PAGE_REPLACING_VERBS = ("recast", "morph", "remake")`, `PAGE_LEAVE_S = 1.0`.
  The four verbs **not** in the replacing set keep the same page — `rescale`
  retargets the axes, `extend` grows the window, `park` makes room, `compare`
  morphs a figure the page already wrote — so nothing leaves on them. `remake` is
  new to the bracket's set too (it re-writes the whole chart).
- `:882` `stamp_page_leave(row_species)` → `(stamped, clamped, dropped)`. Three
  things it decides, and all three are the compiler's **so a gate can read them**
  (the reviewer's HIGH: a player clock nothing measures is a lie in the timeline,
  and the shot table, `gate_motion_density` and M21's deployed life all credit a
  species for its `dur`):
  - `leave_at` / `leave_s` — the retract's clock, from the first replacing verb
    at or after the species' word; the first verb wins; idempotent.
  - **the `dur` clamp** — `dur` is cut to `page_species_end(e) - at`, so an
    authored duration never outlasts the page and the hand finishes writing
    inside the room it has. `leave_clamped: True` is the record of why, beside
    the hold pass's own `held`.
  - **the drop** — a species whose replacing verb fires on its **own word** is
    removed from the row, not written-then-retracted, the way `HOLD_MIN_S`
    refuses a flash (2026-09-08). No gate and no player ever sees it.
- `:998` `page_species_end(entry)` — `leave_at + leave_s`, or `None` for a
  species that stands. **It has a caller now:** the clamp above computes the room
  with it, so the timeline's `at + dur` and the page's own end are the same
  number.
- `:1012` — `keep` validated: a bool, and only on a page-bound species.
- `:5335` — the pass wired into the row loop after the hold pass has settled every
  `dur` and before the row is validated, printing what it did (below).
- `docs/content-video-engine/samples/scene-evidence-engine.mjs:11056` —
  `pageLeave(sp, t)`: `segEase(clamp01((t - leave_at) / leave_s))`, the page's own
  1.0 s (`LP_RETRACT.COLOURS`) so nothing pops; `0` for everything nothing
  replaced the page of, which is every species in every golden.
- `:11069` the bracket honours `keep` and the `remake`; `:11073` the spread's
  `fill-opacity`; `:11082` the figure's group opacity; `:11089` the note's
  opacity; `:11112` the retitle un-writes glyph by glyph on the leave.

### The compile lines, verbatim

```
  page leave: 1 page-bound species retract with their page on row 3 (note) - R26-219
  page leave: dur clamped to the leave on row 3: note 10s -> 2s
  page leave: dropped 1 note on row 3 - the chart_to that replaces the page fires on the species' own word, so there is nothing to write
```

(`f"{k} {was:g}s -> {now:g}s"`, so `10.0 → 10` and `2.0 → 2`; the row number is
the 1-based shot row, and the kinds are sorted and joined by `/`.)

### The retitle's `--w` read-back at `:11112` — said out loud

The reviewer's purity note, and it is deliberate. The retitle leave is the **one**
place in this layer that multiplies the `--w` the DOM carries rather than the
`__w` the engine keeps, and the reason is composition: a retitle can be *both*
erased by the next title and taken by the page, and the chain above writes `--w`
from `__w` every frame as a pure function of `t` — so multiplying what **this
frame** wrote is still pure in `t` (paint the same instant twice, the same bits),
where multiplying `__w` would throw the chain's erase away. R26-46's integrator is
the case where the read **feeds itself across frames**; this factor never writes
`__w`, so it cannot. The same paragraph now sits in the code at `:11112`.

### Measured, before → after

The H unit's own instants, a three-series page recast at 14.0 s, the note written
at 6.0 s (note `div` opacity read on the served player):

| t | before | after |
| --- | --- | --- |
| 13.5 (its own page) | 1 | 1 |
| 14.5 (mid-leave) | **1** | 0.5 (retracting) |
| 15.05 (leave done) | **1** | **0** |
| 22.0 (the row's *eight seconds later*) | **1** | **0** |
| with `keep: true`, 22.0 | 1 | 1 |

And in the timeline, a note authored `dur: 10` under a recast 1.2 s later: `dur`
**10.0 → 2.2**, so `at + dur` is 8.2 s, exactly `page_species_end`.
