## The defect, measured

The operator read a **bare** page at "like 20% size". Two reservations made that square, and a third
thing hid how bad it was:

| | |
| --- | --- |
| the CAPTION's column | a landscape page's chart box is `(0.6 if quiet_zone else 0.9) * cb.w`, because the STAGE caption sits in the page's declared quiet zone (`#caption.stage` moved to 58 % of the stage; `caption_strip_x`) |
| the CARD's column | a card was placed in that same reserved third - which E65's placer has not needed since 2026-09-11 |
| the PARK | the H unit parked the page to keep its end tags out of the caption's box: `[180, 236, 403, 244]`, the 21 % the operator measured. Bare and unparked the same geometry gives **784 px, 40.8 %** |

## The change

**THE BOX.** `ledger_page.LAND_FULL` — `{X: 0.0300, Y: 0.1824, W: 0.6948, H: 0.6917}`, in RENDERED
stage fractions (the punch is already in them, so the estimate can be read straight against a frame),
carrying the chart's own **1000:560 viewBox aspect** so the SVG's `meet` letterboxes nothing. Three
feet cap it, and every one was measured on the served player rather than reasoned about:

1. **the inline END TAGS stay on the stage.** The dense-line species writes each series' name beside
   its last point, in the chart's own units, so a tag grows with the chart. The first pass put the box
   on the whole stage and ran them **305 px off the right of the frame**. `X + LAND_TAG_REACH * W <=
   0.979` is what caps `W` at 1334 px. `X` is not free either: at `X = 0.010` the y tick column landed
   36 px outside the 16:9 `SAFE_BOX`, and every pixel `X` gains costs `LAND_TAG_REACH` of `W`.
2. **the x tick labels clear the anchored caption** — their foot is `LAND_TICK_B` (0.911) of the box's
   height: `197 + 0.911 * 747 = 878`, level with `CAPTION_ANCHOR["16:9"]`'s top and 39 px clear of the
   caption's own one-line box (measured at y 919-960: the strip is two lines and the caption sits at
   its foot).
3. **the source line clears the strip's foot** — written `LAND_SRC_GAP` under the box it runs
   959-1000, under the strip's 960, which is where the landscape source line sits today.

(2) and (3) pull against each other — a taller box drops the ticks into the strip, a shorter one lifts
the source into it — and together they hold the height inside 4 px. Nothing in `LAND_FULL` is free to
be rounded.

**THE CAPTION.** At 16:9 a LEDGER PAGE row's caption takes the anchored strip **by default**; until
now only a live dock ever demoted a caption there. The door is the one the engine already had —
`page.caption === "anchor"`, the host plate's (C5) — so the player needed no new branch for the
decision: `capPinned` → `.quiet` → `#caption`'s own `left/right: 145; bottom: 120`, which IS
`CAPTION_ANCHOR["16:9"]`. STAGE mode is untouched everywhere it already was: a PLATE row keeps it at
both aspects (a plate has no plot to be in the column of), and a 9:16 page keeps it because a portrait
page's stage caption already has its own strip under the page (`#caption.stage.onpage`).

**THE CARD.** No column is kept for it. `free_bands`' `right` band now starts after the page's own
**end tag column** (`page_boxes["tags"]`) instead of at the plot's edge — without that the placer put
the card straight across `+613% MEMORY MAKERS (hynix+Micron)`, measured on the frame. The column is
estimated from this page's own series names at **two advances**, because the element is two type sizes
(the name in the big bold, then the badge that keys that line in its own smaller type — E22's dynamic
label, matched to its series by `BADGE_ACCENT_COL`, the mirror of the engine's `LP_BADGE_COL`). One
advance could bound neither: a short mixed-case name measures 14.8 units a glyph, an all-caps one 18.8,
and a name diluted by a long badge tag 13.0. 19.0 / 5.0 is an upper bound on all five tags measured,
which is the side to be wrong on.

## What I could not do, with a path:line

- **70 % of the stage width, which the brief asked for.** The plot is `(1 - L - R) = 0.710` of the
  chart (`buildLedgerLine`: `L = 70, R = 220` of 1000), so 1344 px of plot needs a chart 1893 px wide
  and — at the viewBox's own aspect — 1060 px tall, which is the whole 1920x1080 stage: no band left
  for the title and the sub above the plot, and the x tick labels under the anchored caption. Two
  things have to move first and neither is this row's: (1) the inline END TAG would take portrait's
  treatment (right-anchored above the line's end, the `P` branch in `buildLedgerLine`) instead of its
  own column beside the line — a visible change to an approved species, which is the operator's call;
  (2) the chart's viewBox would have to follow the box's aspect instead of letterboxing inside it, and
  the seven landscape builders' margins are absolute viewBox units (`L/R/T/B = 70/220/40/470`), so
  that is a refactor, not a line. **50.3 % is the ceiling with the tags beside the lines**, and the
  binding constraint is arithmetic, not taste: `X + LAND_TAG_REACH * W <= 0.979`.
- **the fixture was not re-measured.** `content/video_engine/assets/page-boxes.v1.json` is outside this
  lane's write set, so a full-stage page is **ESTIMATED**, not measured — `page_boxes["measured"]` is
  False and the build prints its own line saying so. Two consequences to know about: E65's `empty` and
  `axis` rooms need the measured `data_mask` (`mask_rooms` and `axis_room` both return nothing without
  it), so a card on a full-stage page falls through to `outside` or, when the page's names take the
  whole band, to `corner` with the build's WARN; and the estimate carries no Ken Burns.
  `measure_page_boxes.py --write` closes both, and it is one command against a generated fixture.
- **`docs_find "caption strip 16:9"` still answers with the audit, not with the capability row.** The
  `[capabilities]` layer is generated (`docs/CAPABILITIES-INDEX.md` and the eight `docs/DOCS-*.jsonl`),
  `docs_find` reports all eight **already stale** on this tree from other lanes' edits, and
  `build_docs_layers.py --write` is a repo-wide regeneration this lane must not take (R26-92, the wall
  the R26-219 lane hit). The row is on disk in `CAPABILITIES.md`; the layer rebuild is owed.
- **the caption's SIZE at 16:9 is untouched, and it is a decision the operator has not made.** A page
  row's caption now renders at the landscape quiet size, **33 px / 600** — the template says that size
  was deliberately left alone when E62 raised the portrait floor to 48 / 800 (*"16:9 is above its
  own"*, `scene-evidence-player.template.html:305-317`). But E62's own principle is *"the demotion is
  in POSITION, not in size"*, and until this row a 16:9 page's caption was 64 px / 800; every page
  row's caption is now the smaller type. Two lines at 64 px are 143 px and the strip is 82, so keeping
  the stage size there is not a dial — it is a taller strip or a one-line caption page, which is the
  operator's call and E99 s82 (f)'s own neighbour ("labels sized for the phone at 16:9 — a number, not
  a feeling"). **Judge this on the frame before the H unit is built.**
- **no H-unit or project file was touched** — the brief forbids it. The H unit's page row still carries
  the PARK that was put there to keep its end tags out of the caption's box; with the caption in the
  strip that park has nothing left to do, and removing it is T-side work.
- **the pre-existing whole-tree failures (R26-224) were not re-measured** — the brief's command is the
  five files above. The main checkout was already dirty when this lane began, and another lane wrote
  to `tests/golden/` and to the engine file while it ran; nothing outside this lane's write set was
