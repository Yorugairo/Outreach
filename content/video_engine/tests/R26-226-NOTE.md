## What was there, measured

A dense-line page draws every series on ONE clock. `lpPaintChart`
(`scene-evidence-engine.mjs:11539`, before this row) opened each path with

```js
const fr = clamp01((c - pp.stagger * 0.3) / 0.7);
```

— `c` is the page's whole build fraction and `stagger` is `i / N`, so the four lines crawl forward
side by side and land within a third of a clock of each other. Read on the served player, the same
four-series page with no token, at t = 5.75 s: **f = 0.988 / 0.976 / 0.949 / 0.892** — four lines
moving together, a spread of 0.096. The only way to put one line before another was a `build_to` per
spoken phrase, which is the crawl that stops.

## The token, and why that form

**`;build=lines`**, or **`;build=lines:<s>`**, on the ledger plate id. Three reasons for that spelling:

1. **It names a page-level BUILD MODE, not a species.** The sequence is how this page draws at all —
   not a thing that happens on a word — so it belongs on the plate id beside `;domain=` and `;form=`,
   and `build_to` stays exactly what it is: the authored stop the ruling allows (*"it would be
   different if we were stopping to talk about each section"*), still capping its own series inside
   that series' own window.
2. **The optional setting is ONE series' seconds**, not the page's total, because the author is timing
   a LINE against a sentence. The page's total is arithmetic (N × s) and the compiler does it, writing
   `build_s` — the single key the engine's `buildDur` (`:7887`) and the motion gate's landing
   (`gate_motion_density.py:1215`) both already read. One truth, not two clocks.
3. **The mode is a WORD**, so a second mode (a bars page's own order, say) joins `PAGE_BUILD_MODES`
   without a second token, and anything else is refused by name at the parser — the one place the
   grammar pass and the page pass both go through.

A row that names none writes nothing: every page compiled before this row is byte-identical.

## The reviewer's round — a series held at index 0 takes NO turn

The MEDIUM, and it is right: the build beat is spent on the first cap (`prev = capFrac(pp, index);
f = f * prev`) and **`capFrac` at index 0 is 0** (`scene-evidence-engine.mjs:10021-:10025`), so a series
staged for a later reveal drew NOTHING through a whole turn — a dead beat of still axes, which is the
crawl ruling's exact enemy.

So a **turn belongs to a series that actually DRAWS when the page opens**. `lineBuildNow` (`:8800`)
filters the load-time series list by `lpFirstCapIndex` — the earliest `build_to` by `at`, a cap naming
no series applying to every one, exactly as the paint's own `forMe` reads them — and a held series gets
`fr = 1`, which its own cap (0) then holds at nothing until the word that reveals it. **A turn keeps its
own length** (`n` stays the page's series COUNT), so the row's `;build=lines:1.2` still draws 1.2 s
lines: the lines that draw come earlier and the BUILD ENDS earlier, never a pause inside it. When every
series is held at 0 the page's own order stands (each line is 0 through the build either way, and an
empty window list would be a thing a reader has to interpret).

Which series take a turn depends on the row's SPECIES, which `buildLedgerLine` never sees — so the load
stamps the series and the paint decides, off the same `caps` the fork reads. One truth, no second copy.
The compiler stamps the same windows through `line_build_first_cap` (`build_scene_timeline_f.py:3723`),
the one reading written once.

Measured on the served player (series 0 staged: `build_to index 0` at the build's open, and a reveal at
20.0 s): at **t = 4.6** — 0.2 s into the build — series 1 is already drawing at **f 0.685** while series
0 is at 0 (before the fix the page held 1.2 s of still axes); by **t = 8.0** all three drawing lines are
whole (three turns, 4.4→8.0) and the build has ended a turn early; at **t = 21.0** series 0 arrives
whole on its own clock. A cap at index > 0 is untouched — it IS the line drawing — and still takes its
turn.

**The badge needed no code, and that is a finding**: `ledger_page.badges_for` (`:928`) makes a badge
that keys a dense series `inline`, i.e. that line's own end tag. A rail badge on a dense-line page never
keys a series by construction, so there was no badge clock to re-time.

## The instants are measured, not chosen

The build's easing is `expoOut` (the pen law `strokeFrac` answers null unless `curvature_stroke` is on),
which is heavily front-loaded: at HALF of a series' own window a line is already **96.9 %** drawn
(1 − 2⁻⁵; measured, dashoffset 37 of 1183). A line reads as DRAWING at u = 0.125 of its window —
1 − 2⁻¹·²⁵ = **0.580** of its length, 0.15 s into a 1.2 s window — which is where both goldens sit.

## What I could not do, with a path:line

- **`;order=2,0,1` is NOT built.** The sequence is the page's own series order

  row's span, which every plate option is currently blind to.
- **The bare mode on a page with ONE authored `build_to` per phrase is not detected.** A row may still
  author the crawl-that-stops by hand; the mode makes the default right, it does not forbid the old
