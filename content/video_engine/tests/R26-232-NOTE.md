### (1) A caption page is an event wherever the PAGE puts it — and the PIN is the door

R26-205 stamps a full-stage 16:9 ledger row `caption: "anchor"` + `full_stage: true`, and the compiler
then stamps every caption page over it `cap_mode: "anchor"` — the page IS the plate, so there is no
stage left for the strip to take. The gate's `== "stage"` filter therefore counted the H bed's 24
anchored pages, one every ~1.75 s, as 42 s of stillness.

What the player actually paints in that register, read in the engine rather than assumed:

- the page TURN is motion — `opacity 0 → 1`, `translateY(12px) → 0`, `scale(1.14) → 1` over .28–.34 s,
  the `if (g && !quiet && !stage)` branch at `:16220`, which is the branch a pinned caption falls into;
- each WORD still changes on its own spoken time — `ws[j].classList.toggle("on", on)` (`:16238`) fires in
  every register and `#caption .cw.on { color: #fff }` (`scene-evidence-player.template.html:517`) is not
  scoped to `.stage`. What the anchor does NOT get is the per-word POP:
  `#caption.quiet .cw { transform: none !important }` (`:515`) kills the scale and the pop / fade-up /
  phrase branches all stand behind `stage` (`:16236` / `:16262`, `:16279`, `:16297`). So an anchored
  word's onset is a **weaker beat** — a colour change, not a punch — and on a pinned page it is counted
  as one event all the same;
- the fade-up ENVELOPE is a stage device (`fuArrive = stage && …`, `:16236`), so an anchored page reads
  its RAW onsets and never `_stagger_starts` — the gate credits motion when the player moves it.

**The one deviation from the dispatch, and why.** The brief said "an anchored page counts exactly as a
stage page does". It does — **on the row R26-205 pins**. Credited on *every* anchored page, the same
change greens episode one: `build-f` carries 354 lower-third anchored pages over Ken Burns plates and no
ledger page at all, and with them counted its stillness rows go quiet — measured on the way through:
`M10 PASS 'no still stretch > 6s begins in the first 60s'` on the cut whose pinned expectation is
`FAIL ... 0:57+14s`, with the three ep1-red tests in `test_gate_motion_density.py` failing
(`test_red_steel_and_paper_as_shipped`, `test_ep1_reads_its_own_timeline_clock_and_stays_red`,
`test_red_steel_and_paper_opening_minute_and_chart_holds`), and `test_caption_arrive.py`'s
`test_m08_still_fails_when_the_stretch_carries_anchor_pages_under_a_fade_up_timeline` with them. Ep1 is
the one cut with an operator verdict on exactly this question (E21, "ep1 died of VISUAL stillness"), and
a gate that calls it alive is a gate calibrated against nothing. So the register is credited **where the
page forced it** and nowhere else. If the operator widens it to every anchored page, `_pinned_page_at`
(`:700`) is the single predicate to open — and ep1's three red rows go with it.

### (2) The chosen term: a sustained-life event every **1.613 s** inside a live page's span

Of the two options in the brief I took the **sustained-life term**, not the INFO downgrade:

1. **It measures instead of excusing.** The INFO branch would suppress a row on the strength of what the
   row *declared* (`idle=live`); the term states what the frame *does*. And a downgrade inside the span
   would hide a genuinely dead stretch there (a page whose kinetics switch the idle off, say) - the term
   cannot: `_page_idle_live` returns False unless `kinetics.idle is True`, exactly as `idleOf` does
   (`:7584`), so a build with the idle off keeps its FAIL. The test for it is
   `test_the_page_must_actually_render_the_life_the_row_asked_for`.
2. **The gate already had the vocabulary.** A continuous life (steam) and a video dock are credited one
   event per `LIFE_CONTINUOUS_S` = 1.0 s. Not crediting the page's interior was the defect, not a
   missing concept.
3. **The number is measured, and it is the conservative end of the measurement.** R26-228 derived the
   lead point's spark rate rather than guessing it: `0.40 @ 0.62 Hz`, "period 1.613 s ... incommensurate
   with the 2 s tile window, the 12 fps frozen-frames grid and the 24 fps render" (`R26-228-NOTE.md:194`).
   Every other element of that life is faster or continuous (the stroke's bloom pulses with the tip), so
   the spark's period is the **slowest named cycle** — one full pulse of the lead point per credited
   event. It clears `SHORT_PULSE_MAX_S` (2.5 s) by 0.9 s and no more: a live page's span passes the
   pulse; a gap a live page does not cover still FAILs.
4. **It rests on the part of the life the operator kept.** E99 s83, the same evening, on this bed's copy
   f: "remove the interior drift, keep the electric/glow etc let that carry the life" — the per-word walk
   goes (R26-234), "the lead point's spark and halo ... the stroke's bloom pulse" stay. The term is the
   spark's period, so R26-234 lands without moving this number.

Scope: the term is in `pulse_events` / `pulse_still` only. **M01 / M02 / M03 / M07 read the frame's own
events, unchanged** — `test_the_life_term_is_the_pulse_rows_only` pins it (M01 still FAILs a 20.6 s hold
while M16 passes it, which is the brief's "no other gate row changes" read literally).

Which term fired is printed in the row's own text (`_life_term`, `:847`):
