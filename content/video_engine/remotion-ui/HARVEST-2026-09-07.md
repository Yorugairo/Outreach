## The loading note

**Installed as references; loading into a workspace is a separate step per component.** That step is: a Remotion project —
`remotion-ui.json:5-8` declares `"remotion": { "version": "4", "config": "remotion.config.ts", "root": "src/Root.tsx" }` —
with the alias map resolved on the import path:

```json

    "primitives": "@/remotion/primitives",
    "scenes": "@/remotion/scenes",
    "compositions": "@/compositions",
    "lib": "@/remotion/lib",
    "hooks": "@/remotion/hooks"
  }

plus the npm packages each file imports (`remotion`, `@remotion/transitions`, `@remotion/google-fonts`, `maplibre-gl`) — none
of which are installed here; there is no `node_modules`, no `remotion.config.ts` and no `src/Root.tsx` in this folder.

**Ours is not a Remotion player.** Our runtime is the single-document template
`docs/content-video-engine/samples/scene-evidence-player.template.html` driven by the kinetics modules
`content/video_engine/scripts/kinetics/{ease,spring,stroke,ink,squash,idle,stopaction,arap}.mjs`. So a port is never a copy of
a `.tsx`: it means **re-expressing the maths** in the template or in a kinetics module as a pure function of `t`, exactly as
the HyperFrames harvest did (mechanism only, never the runtime). Concretely, every `spring({ damping, stiffness, mass })` call
below is Remotion's solver and would land on our analytic `springEval` / `springPop` in `spring.mjs`; whether the two solvers
agree numerically for a given config is [UNVERIFIED] — it needs one eye test, not an assumption.

```

The load-bearing maths is the coverage law — the scale comes from the distance to the **furthest corner**, not the frame width:

```tsx
src/remotion/primitives/svg-mask-reveal.tsx:90-98
  const reach = Math.max(
    Math.hypot(cx, cy),
    Math.hypot(width - cx, cy),
    Math.hypot(cx, height - cy),
    Math.hypot(width - cx, height - cy),
  );
  // The presets are authored on a 0–100 box, so half a box is 50 units; the
  // scale that puts the shape's edge on the far corner is reach / 50.
  const scale = (progress * reach * 2) / 100;
```

The mask is a binary SVG `<mask>` (`<rect fill="#000">` under a `<path fill="#fff">`, `:105-111`) — a **hard edge**, not a
feather — and the file states why it is a `<mask>` rather than a `clip-path` (`:50-51`): so the same shape *can* carry soft
edges, and so any `d` authored elsewhere drops straight in.

**(b) What we already have that is similar.** The `snap` page enter (a landed card grows to become the world); the `mount` and
`suck` transitions and the restored hard-edge clip wipe (E47/E48); `stroke.mjs`'s two-thirds-law draw-on for shape arrivals;
`undraw` as the page species that removes a thing; `arap.mjs` for outline morphs, and `radial` as a species.

**(c) Gap it fills.** Our reveals are rectangular or world-scale; there is no **shape-masked reveal from an arbitrary origin**,
and no coverage law that guarantees an off-centre reveal actually covers the frame. `snap` grows a card into the world; this
grows a hole in the shape of anything into the world.

**(d) Optimal use in our lane.** Not as a component — as three lines of maths inside the template. The
reach-to-furthest-corner scale is the correct generalisation of `snap` for the common case where the card that just landed is
not in the middle of the page. The hard-edged mask sits on the right side of the 2026-08-30 precedent (that port was rejected
because its feathered wipe read as a fade); a binary mask cannot read as a fade. And under E50, `invert: true` — the shape
shrinking back over the content — is exactly the "un-draw or become the next thing" exit a deployed chart owes at 6–8 s from
its last data mark.

**(e) Verdict: backlog.** A bounded maths port (the coverage law, plus `invert` as a shape-shaped un-draw) into the template's
`snap`/mount, taken up when a slice asks for it — it needs no new runtime and no new species.

Two springs, deliberately offset — the scale clamps its overshoot, the rotation is left free to overshoot and trails:

```tsx
src/remotion/primitives/badge-stamp.tsx:72-92
  // `overshootClamping` because this spring drives scale: an overshoot past 1
  // dips the settled seal under its own size, which reads as a wobble rather
  // than as weight. The rotation spring below is free to overshoot.
  const land = spring({ frame: frame - delayInFrames, fps,
    config: { damping: 14, stiffness: 220, mass: 0.9, overshootClamping: true } });
  // Rotation trails the scale by its own spring: the seal is still turning
  // fractionally after it has stopped moving toward the page.
  const settle = spring({ frame: frame - delayInFrames, fps,
    config: { damping: 11, stiffness: 120, mass: 1 } });
  const scale = interpolate(land, [0, 1], [2.1, 1], { ...clamp, output: "perceptual-scale" });
  const turn = interpolate(settle, [0, 1], [rotation + windUp, rotation], clamp);
```

and the shockwave split into **two** curves rather than one, with the failure it fixes written down (`:98-117`): `shockLife` is
linear over 14 frames (it fades and thins the ring evenly), `shock` is the eased-out expansion to twice the seal's radius,
because one shared ease-in produced "an impact ring nobody ever saw". Ink strength decays `1 → 0.86` as the pressure comes off
(`:96`), and the ring is thrown from the impact frame, never from the start, so "it cannot arrive before the thing that caused
it" (`:47-49`).

**(b) What we already have that is similar.** `stopaction.mjs` (throw/land with weight, contact shadow, ground dip);
`spring.mjs`'s analytic `springPop` / `springEval`; `squash.mjs`; the docks that spring, throw or land (E45 park
choreography); the `snap` page enter; `callout` and `bracket` for a labelled mark on the page.

**(c) Gap it fills.** Two. First, a **stamp/seal species** — none of our page species (`build_to`, `bracket`, `retitle`,
`relight`, `undraw`, `figure`, `note`) and none of the effect species stamps a verdict onto the page. Second, and worth more:
the **two-spring offset**. Our landings settle on one spring; the offset between a clamped scale spring and a free rotation
spring is a weight cue we do not have (the continuous cousin of HF-2's one-frame lag, already booked into P47 T1).

**(d) Optimal use in our lane.** The mechanism ports; the look does not — a gold ring set in `ui-sans-serif` is not the ledger
world, so the seal would be drawn in our hand (Kalam, charcoal on cream, the ring drawn on by `stroke.mjs`) with the shockwave
as an ink-pressure ring rather than a stroke. Its natural beat is the verdict page: the number lands, the seal lands on it, and
the ground answers. Note `exitAtInFrames` — it ships with a leave dial, which is E50's shape (a deployed mark either leaves or
becomes the next thing) and the reason to author the stamp with its exit from the first build. Under E51 a landed stamp is a
legitimate anchor for a push-in, since a push tied to a newly landed element is precisely what E51 permits.

**(e) Verdict: priority integration.** The two-spring offset and the split shock curves are small, sound and land straight in
the `stopaction.mjs` / `land` work already in flight; the seal itself is a species we lack and the ledger world can carry.

**(a) What it does, from its source.** A whole-frame 3-D flip in which each scene turns its own half-circle and backface
culling does the hand-off.

```tsx
src/remotion/primitives/transition-card-flip.tsx:11-27
export type CardFlipProps = {
  /** `y` flips left-to-right like a page; `x` flips top-over-bottom. */
  axis?: CardFlipAxis;
  /** Perspective distance in px. Lower is a more aggressive, wide-angle flip. */
  perspective?: number;
  /**

  /** Peak darkening of the face turning away, 0→1. */

  /** How far the card recedes at the halfway point, as a multiple. */

```

Three pieces of maths, each with its failure recorded. The turn is a full 180° per scene and is never clamped at 90°
(`:58-63`: clamping "would leave both faces parked edge-on and flickering against each other"). The recede is parabolic and
therefore exactly neutral at both ends (`:65-67`: `away = 4 * displace * (1 - displace)`, `scale = 1 - (1 - dip) * away`). The
shading is physical (`:69-71`: `facing = |cos(turn)|`, "the physically-right curve and is exactly 1 at 0°"). And the seam rule:

```tsx
src/remotion/primitives/transition-card-flip.tsx:81-86
        // Only the outgoing layer paints the backdrop: it sits underneath the
        // incoming one for the whole cut, so one opaque plate covers the seam
        // and the incoming layer stays free to composite over the outgoing
        // scene rather than over a slab of colour.
        backgroundColor: phase.isEntering ? undefined : backdrop,
```

with the rest-state contract enforced up front (`:52-56`: `displace <= 0` returns the children untouched — "which is the whole
contract").

**(b) What we already have that is similar.** The E47/E48 primaries `dip` (through black), `spiral` (the hero), `mount`,
`suck`, `cut`; the `snap` page enter (a landed card grows to become the world); the docks that spring, throw or land (E45); and
HyperFrames' `morph-swap` "condense" register, already harvested as the dock-to-dock hand-over candidate.

**(c) Gap it fills.** A page that turns over to become the next page — a hand-off register we do not have. `snap` grows,
`morph-swap` condenses through a shared silhouette, `dip` goes through black; none of them keeps the same rectangle and shows
its other face.

**(d) Optimal use in our lane.** A ledger page flipping to its reverse is, unusually for a 3-D transition, *on* theme: the
world is paper. Read against the rejected-wipe precedent (2026-08-30 — the feathered directional wipe was rejected because it
read as a fade, and the hard-edge clip wipe was restored), this one sits on the right side of the line: it is a hard, opaque
hand-off with backface culling and an explicit rule that the page background must never show, so it cannot degrade into a
dissolve. The risk is register, not mechanism — a full-frame flip is a game-show move if it is not earned, and E48 says the
primaries are decided by the next builds' curves, not by a catalogue. The seam rule (only the outgoing layer paints the
backdrop) is worth taking regardless of the flip: it is the general answer for any transition that can expose the page.

**(e) Verdict: explore.** Author one flip on a build page and watch it against `dip` and `spiral` before it goes anywhere near
the primary set; take the backdrop-on-the-outgoing-layer rule now, because that one is a correctness fix, not a taste call.

## What this is not

- **Not a change to the engine.** Nothing in `scene-evidence-player.template.html`, the kinetics modules, the compiler or the
  gates changes because of this harvest. Every "port" above is a candidate slice, taken up when a build asks for it and the
  operator says so.
- **Not the Remotion runtime.** As with P35 and the HyperFrames harvest, a mechanism crosses as maths on our painter — a pure
  function of `t` behind a kinetics flag — never as a React component or a Remotion `TransitionSeries`.

  ([UNVERIFIED], above), which is a second reason a port re-expresses the maths instead of copying the file.
